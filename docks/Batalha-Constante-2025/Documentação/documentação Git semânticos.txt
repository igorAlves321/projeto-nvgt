
## Documentação sobre Commits Semânticos no Git

### Introdução

Commits semânticos são uma prática no Git que busca padronizar as mensagens de commit, tornando-as mais informativas e consistentes. Essa prática ajuda a manter um histórico de commits mais claro e facilita a colaboração em projetos de desenvolvimento. As mensagens de commit semânticas seguem um formato específico que indica o tipo de mudança feita no código, permitindo uma compreensão rápida do que foi alterado sem precisar ler todo o código modificado.

### Estrutura dos Commits Semânticos

A estrutura básica de uma mensagem de commit semântica é a seguinte:

```
<tipo>(escopo opcional): <descrição>
```

- **tipo**: Indica a categoria da mudança.
- **escopo (opcional)**: Indica a parte do código que foi afetada.
- **descrição**: Um resumo breve da mudança realizada.

### Principais Tipos de Commits

1. **feat**: Usado para a adição de uma nova funcionalidade.
    - **Exemplo**:
      ```
      feat(usuario): adicionar funcionalidade de login
      ```

2. **fix**: Usado para correções de bugs.
    - **Exemplo**:
      ```
      fix(cadastro): corrigir erro no formulário de cadastro
      ```

3. **docs**: Usado para mudanças na documentação.
    - **Exemplo**:
      ```
      docs(README): atualizar instruções de instalação
      ```

4. **style**: Usado para mudanças que não afetam o significado do código (espaços, formatação, ponto e vírgula, etc).
    - **Exemplo**:
      ```
      style(formulario): ajustar indentação do código
      ```

5. **refactor**: Usado para mudanças no código que não corrigem bugs nem adicionam funcionalidades, como refatorações.
    - **Exemplo**:
      ```
      refactor(api): melhorar a estrutura do controlador
      ```

6. **test**: Usado para adição ou modificação de testes.
    - **Exemplo**:
      ```
      test(serviço): adicionar testes para serviço de autenticação
      ```

7. **chore**: Usado para mudanças no processo de build ou ferramentas auxiliares e bibliotecas, como configurações do CI/CD.
    - **Exemplo**:
      ```
      chore(dependencies): atualizar dependências do projeto
      ```

8. **perf**: Usado para mudanças que melhoram o desempenho.
    - **Exemplo**:
      ```
      perf(consulta): otimizar consulta ao banco de dados
      ```

9. **build**: Usado para mudanças que afetam o sistema de build ou dependências externas (como gulp, npm, yarn).
    - **Exemplo**:
      ```
      build(docker): adicionar configuração do Docker
      ```

10. **ci**: Usado para mudanças na configuração de integração contínua.
    - **Exemplo**:
      ```
      ci(travis): configurar Travis CI
      ```

### Exemplo de Mensagem de Commit Completa

```
feat(pagamento): adicionar suporte a pagamento com cartão de crédito

- Adicionado módulo para processar pagamentos com cartão de crédito.
- Atualizado serviço de pagamento para incluir novas opções.
- Adicionado testes unitários para o novo módulo.

BREAKING CHANGE: a interface do serviço de pagamento foi modificada para suportar múltiplas opções de pagamento.
```

### Conclusão

Commits semânticos melhoram a clareza e a manutenção de um projeto ao padronizar as mensagens de commit. Essa prática facilita a comunicação dentro da equipe de desenvolvimento e ajuda a manter um histórico de mudanças claro e organizado. Adotar commits semânticos pode ser uma excelente maneira de melhorar a qualidade do seu processo de desenvolvimento e a colaboração dentro da equipe.
